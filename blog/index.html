闭包问题​

测试代码
function log(t) {
  console.log(t)
}

const ary = [1, 2, 3]
let s = 0

ary.forEach(function aryCallBack(i) {
  log(i)
  s += i
})
  • s: 用于累加计算,在回调函数中被引用和修改
  • log: 作为函数在回调函数中被调用

这两个变量都来自外部作用域,并在内部函数中被使用,因此都会被保存在闭包环境中

转义字符​

测试代码
$.post({
  api: '/api/createComments',
  data: {
    content: '&lt;script&gt;while(true){}&lt;&#x2F;script&gt;'
  }
})

这段代码不存在安全问题，因为发送的内容中的特殊字符已经被转义处理了。

css 中的特异性​

测试代码
<style>
  :is(.box) h1 {
     color: red;
  }
  :where(#box) h1 {
    color: green;
  }
  div h1 {
    color: yellow;
  }
</style>

<div class="box" id="box">
  <h1>知乎</h1>
</div>
  1. :is()和:where()的主要区别在于特异性计算方式:
  • :is() 会采用其括号内最高的特异性
  • :where() 的特异性永远为 0
  1. 具体分析各选择器的特异性:
  • :is(.box) h1: 类选择器(.box)的特异性为(0,1,0)
  • :where(#box) h1: 特异性为(0,0,0)，因为:where()将特异性重置为 0
  • div h1: 标签选择器的特异性为(0,0,2)

css 的 rel 属性​

当前页面使用了同源的 web 字体，使用<link rel="preload" href="xx/yy.woff2" .../>

  • preload 指令可以让浏览器提前加载指定资源,不需要等到解析到相应位置才开始加载,

  • prefetch 是一种低优先级的资源预加载方式,通常用于加载其他页面可能会用到的资源,不适合加载当前页面的必需资源。

  • preconnect 用于提前建立与服务器的连接,包括 DNS 查找、TCP 握手和 TLS 协商,但不会下载资源本身,对于同源资源没有明显优势。

  • prerender 用于预先渲染整个页面,对单个字体文件的加载没有帮助,而且资源消耗较大。

操作系统的发展和分类​

发展阶段主要缺点主要优点
手工操作阶段用户独占全机、人际速度矛盾导致资源利用率极低
批处理阶段——单道批处理系统内存中仅能有一道程序运行，CPU 有大量的时间是在空闲等待 I/O 完成缓解了一定程度的人机速度矛盾，资源利用率有所提升
批处理阶段——多道批处理系统用户响应时间长，没有人机交互功能（用户提交完作业后智能等待计算机处理完成，中间不能控制自己的作业执行）多道程序并发执行，共享计算机资源。资源利用率大幅提升，CPU 和其他资源更能保持“忙碌”的状态，系统吞吐量增大
分时操作系统不能优先处理一些紧急任务用户请求可以被即时响应，解决了人机交互问题。允许多个用户同时使用一台电脑，并且操作相互独立
实施操作系统能够优先响应一些紧急任务，某些紧急任务不需时间片排队

三层调度的联系、对比​

要做什么调度发生在发生频率对进程状态的影响
高级调度按一定的原则从外村的作业后备队列中挑选一个作业调入内存，并创建进程外存 ➡ 内存（面向作业）最低无 ➡ 创建态 ➡ 就绪态
中级调度按照某种策略决定将哪个处于挂起状态的进程重新调入内存外存 ➡ 内存（面向进程）中等挂起态 ➡ 就绪态
低级调度按照某种策略从就绪队列中选取一个进程，将处理机分配给它内存 ➡CPU最高就绪态 ➡ 运行态

调度算法​

基础服务算法思想算法规则用于作业/进程调度是否可抢占优缺点是否会导致饥饿
先进先服务从“公平”的角度考虑按照先后顺序进行服务用于作业调度时，考虑的是哪个作业先到达后被队列；用于进程调度时，考虑的是哪个进程先到达就绪队列非抢占式公平算法简单 排在长作业后面的短作业需要等待很长时间，带权周转时间狠罚，对短作业来说用户体验不好不会
短作业优先追求最少的平均等待时间，最少的平均周转时间、最少的平均带权周转时间最短的作业/进程优先得到服务两者皆可。用于进程调度时称为“短进程优先算法”非抢占式，但也有抢占式版本——最短剩余时间算法“最短的”平均等待时间、平均周转时间 不公平。对短作业有利，对长作业不利。会
高响应比优先要综合考虑作业/进程的等待时间和要求服务的时间在每次调度时计算各个作业/进程为其服务既可用于作业调度，又可用于进程调度非抢占式综合考虑了等待时间和运行时间（要求服务时间） 等待时间相同时，要求服务时间短的优先（SJF 的优点） 要求服务时间相同时，等待时间长的优先（FCFS 的优点）不会
时间片轮转（RR）公平地、轮流为各个进程服务，让每个进程在一定时间间隔内都可以得到响应按照各进程到达就绪队列地顺序，轮流让各个进程执行一个时间片。用于进程调度（只有作业放入内存建立了相应地进程后，才能被分配处理机时间片）抢占式公平；响应快，适用于分时操作系统 由于高频率的进程切换，因此有一定开销；不区分任务的紧急程度不会
优先级调度越来越多应用场景要求根据任务的紧急程度来决定处理顺序每个作业/进程都有各自的优先级，调度时选择优先级最高的作业/进程既可以用于作业调度，也可用于进程调度。甚至，还会用于在之后会学习的 I/O 调度中抢占式、非抢占式都有。非抢占式只需在进程主动放弃处理机时进行调度即可，而抢占式还需在就绪队列变化时，检查是否会发生抢占用优先级区分紧急程度、重要程度，适用于实时操作系统。可灵活地调整对各种作业/进程的偏好程度 若源源不断地有高优先级进程到来，则可能导致饥饿会
